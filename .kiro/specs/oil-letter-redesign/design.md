# 设计：油画书信体验

本文件由 Codex 为 Kiro 接续整理。具体画面以已交付前端和验收截图为准；本文件不是 Kiro 已运行的证明。

## 体验结构

以“走进花园、收下消息、读懂关心、写一封回信”为体验线索。引导与自由导航使用同一份前端状态，不增加路由框架。阶段切换只改变视图和焦点，不重建或清空输入；新消息使旧结果失效。只有当前可操作阶段进入键盘顺序，隐藏区不接收焦点。

画面层次从油画场景到纸张再到墨色文字。输入与结果采用信纸/聊天气泡语言，艺术标题和正文分别设计。CSS 统一维护颜色、阴影、边框与动效节奏；低动态偏好时取消非必要位移。保留静态背景和系统字体回退。

## 数据路径

```
粘贴消息 + 对象 + 补充内容
  → POST /api/reply
  → 校验和并发/超时边界
  → demo: 本地规则 + 模板
    live: Jev 结构化判断 → LLM 生成
  → 可能含义 + 回复提示 + 可编辑回复
  → 用户核对 → 复制 → 用户在微信粘贴发送
```

保持现有契约：`text/context/recipient/tone/mode/variant` 输入，`possible_meanings/reply_tip/reply/strategy/topic/decision_source/generation_source/meta/note` 输出。将 UI 的多步状态与服务请求状态分离，避免导航误触发生成。

## 错误、隐私与兼容

保留输入校验、Host/Origin 检查、服务超时和取消、真实请求并发限制。新增图片和字体只能通过静态白名单提供，不允许任意路径访问。API 密钥不进入任何客户端资源。真实消息不写浏览器持久存储或访问日志。

复制失败时选中回复并显示手动复制说明。当前页面不调用微信联系人或私人聊天 API。未来部署由独立环境提供 HTTPS，再根据产品需要评估公众号入口、OAuth 或 JS-SDK；普通 H5 粘贴/复制功能不强制增加登录。

## Kiro 接续方式

`.kiro/steering/project.md` 提供持续约束；本目录三份 spec 提供验收依据；`.kiro/hooks/backend-check.json` 在 Kiro IDE 保存服务器/业务/工程测试文件后运行 `npm test`。前端浏览器验收保留为显式任务，因为它依赖本机 Chrome/Playwright 配置。

首个实际 Kiro 任务应是只读审阅：对照 requirements 检查最终前端、API 和测试，指出可复现缺口。用户确认结论后再让 Kiro修复一个具体缺口并保存检查记录。若没有缺口，记录实际审阅结论与执行的验证，不制造不必要改动。

## 验证

复用 `tests/server.test.mjs` 验证边界与模型契约；复用 `tests/browser-smoke.mjs` 验证六类场景、对象/语气、复制回退、失败恢复及小屏布局。补充导航往返、焦点、输入不丢失、reduced-motion 检查；人工复核桌面与手机截图。Kiro hook 的 JSON 结构校验与实际触发应分开记录。
