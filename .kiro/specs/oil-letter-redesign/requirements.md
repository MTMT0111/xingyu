# 需求：言外油画书信体验

记录日期：2026-10-09。依据本轮用户要求整理，由 Codex 编写，尚未在 Kiro 会话内执行或审阅。

## 1. 完整的油画美术语言

作为用户，我希望网站像一幅可以互动的温暖油画，字体和聊天框都经过设计。

1.1 当用户进入页面时，页面应呈现统一的油画色彩、笔触与纸张层次；标题、导航、输入框、回复气泡和按钮都必须延续这套风格。

1.2 当字体或背景资源不可用时，页面应继续使用可读字体与纯色背景，不影响核心操作。

1.3 当视口宽度为 320px、390px 或桌面尺寸时，页面应保持可读、可触控，无水平溢出；输入控件字号至少 16px。

## 2. 顺畅的分段引导

作为用户，我希望被自然引导着完成“收到消息—理解—回复”，也能随时回去修改。

2.1 当用户选择入口或下一步时，页面应展示当前阶段并提供清楚的返回路径。

2.2 当用户返回前一阶段或打开说明时，页面应保留输入和编辑草稿；修改原始消息、对象或补充内容后，必须使旧分析失效。

2.3 当设备偏好减少动态效果时，页面应减少过渡与装饰动画；键盘用户应能访问主要控件并看见焦点。

2.4 当请求进行中或失败时，页面应显示明确状态，避免重复请求；失败后保留输入并允许重试。

## 3. 长辈消息分析与回复

作为用户，我希望针对妈妈、爸爸或其他长辈的消息，得到自然且不替我编造事实的回复。

3.1 当用户提交有效消息时，页面应给出可能含义、回复提示和可编辑的建议回复。

3.2 当用户切换三种语气时，页面应保留原始输入并生成对应表达；失败时恢复先前语气和编辑内容。

3.3 当消息涉及健康断言、未知视频、模糊邀约或催婚时，系统应分别保持审慎、不假装看过、不承诺未知行程、允许有礼貌地表达边界。

3.4 当剪贴板不可用时，页面应提供选中文字的手动复制路径，不能声称已发送给微信联系人。

## 4. Jev + LLM 与微信路径

作为开发者，我希望这版视觉重做保留真实服务接入能力，并能继续演进为微信内打开的 H5。

4.1 当服务端未配置密钥时，系统应明确标为本地演示；配置完成后，真实模式应经 Jev 判断再交给 LLM 生成，密钥不下发浏览器。

4.2 当真实服务失败时，系统应明确报错，不静默套用模板冒充模型结果。

4.3 当前交付应说明微信访问还需要可访问的 HTTPS 地址与 iOS/Android 真机验收；不得把桌面回环地址或微信 User-Agent 模拟等同真机接入完成。

## 5. 可核实的 Kiro 开发证据

作为参赛者，我希望 Kiro 参与可以被核实，而不仅有一个文件夹。

5.1 项目应提供可由 Kiro 读取的 requirements、design、tasks、steering 与自动工程检查 hook。

5.2 如果尚未在已登录的 Kiro 内执行任务，应明确将 Kiro 审阅和 hook 触发保留为未完成。

5.3 完成 Kiro 任务后，应记录版本、任务提示、实际改动/结论和检查结果；不得虚构模型参与记录。
