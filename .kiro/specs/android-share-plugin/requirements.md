# Android 系统分享入口：需求

本规格由 **Codex** 根据当前实现编写，待 Kiro 实际审阅。Kiro 已登录但此前调用返回 `TEMPORARILY_SUSPENDED`（403）；本文件不是 Kiro 已完成审阅或开发的证据。

## 目标与范围

用户从来源 App 的系统分享或选中文字菜单进入星语，确认内容、分析、编辑、复制后返回来源 App。复用现有 Android WebView 和本地 Node / LLM 服务，不增加插件、常驻服务、悬浮窗、无障碍或存储权限。

## 验收要求

1. **系统入口。** `ACTION_SEND` 接收单段 `text/plain`、单张 JPG/PNG/WebP 或单个 MP4/WebM/MOV；`ACTION_PROCESS_TEXT` 接收选中文字。多选不支持，错误内容明确拒绝。微信是否显示系统入口由微信版本和手机 ROM 决定，不能保证。
2. **输入边界。** 文字最多 6000 个 Unicode 字符；图片最多 4 MiB；视频最多 20 MiB、60 秒。原生媒体仅接受本次有读取授权的 `content://`，核对类型、可读性与实际大小；服务端继续验证文件头和媒体内容。不把文件名或普通视频链接当成已经理解的视频。
3. **用户确认。** 收到内容先显示文字或附件信息，不上传、不调用模型。已有输入、附件或回复时显示冲突选项，允许继续原草稿或改用新内容，不静默覆盖；接受后放入编辑区，用户再次主动点击生成才上传和分析。
4. **回复闭环。** 复用现有摘要、可能的理解与编辑回复。复制完整编辑稿后，用户可点“返回原应用”；只返回系统来源栈，不指定聊天、读取联系人、自动粘贴或发送。桥接不可用时允许用系统返回键。
5. **隐私与恢复。** 临时附件不写入公共目录、不申请持久 URI 权限；接受或放弃后释放原生引用。网页草稿只暂存文字，附件不持久化。授权失效或进程回收后明确要求重新分享，不声称草稿或媒体一定恢复。
6. **本地演示。** Debug 仅允许 `http://127.0.0.1:4173` 配合 `adb reverse tcp:4173 tcp:4173`；Release 仍仅 HTTPS。API 密钥只在电脑服务端。系统入口不要求微信 AppID。

## 明确不在当前范围

- 微信直接联系人选择：仍需合格主体的移动应用 AppID、匹配包名及签名；当前个人主体不能申请。
- iOS Share Extension、网页分享目标、多文件批量、后台监听、自动发送、绕过微信限制。
- 本地运行大语言模型权重、额外 Studio 插件或模拟器安装。

当前真实 LLM 独立模式已有 7 个合成样例通过；Jev 可选且尚未配置/验收。没有连接安卓测试机，因此系统入口展示、媒体授权、复制粘贴和返回来源仍需真机验证；此前网页回归不替代此验收。
