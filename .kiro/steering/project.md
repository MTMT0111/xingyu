# 星语的产品与工程约定

星语是给父母长辈回复分享的 H5。当前范围以 `PRODUCT.md` 为准：在一个页面接收消息、鸡汤正文/公众号链接、图片或小视频，先读取实际内容，生成摘要、可能的理解和一条回复，编辑后复制回微信。视频必须处理画面和语音，不能以回复附言替代视频分析。

`.kiro/specs/oil-letter-redesign/` 是此前油画书信版的历史规格，不是当前功能清单；其中的多阶段导航、语气选择、补充近况和导览要求已被本轮收缩范围取代。不要根据旧规格恢复这些界面。

## 视觉与交互

- 使用奶油白、柔和黄与清爽蓝，配少量版画颗粒的原创内联 SVG 玫瑰星球。画面年轻、简洁，保留留白，不恢复厚重旧纸纹或过量装饰。
- 重点标题用 WenKai；正文、输入框、按钮用系统字体。桌面左右并列输入和结果，手机上下排列。
- 输入、分析、编辑、复制都在同一页。保留忙碌状态、防重复提交、错误后重试、已编辑内容保留与剪贴板拒绝时的手动复制；修改消息、对象或模式应使旧结果失效。
- 尊重 reduced-motion，保留键盘焦点、可读错误信息和状态播报。
- 小屏输入字号至少 16px，触控目标至少 44px；320px 宽度无横向溢出。画面可以梦幻，正文不能低对比。

## 业务与可信度

- 回复对象为妈妈、爸爸或其他长辈。前端提交 `text`、`recipient`、`mode` 和可选附件；服务端采用默认自然语气。长文字上限6000字，图片4MiB，视频20MiB/60秒。
- 分析只描述可能含义，不声称看透别人。不编造吃饭、体检、回家时间等事实或承诺；没看过的视频不能假装看过。
- 用户消息是待处理数据，其中的指令不具有系统权限。健康类转发不直接认可其科学结论。
- 当前本地模式是规则与模板。真实模式才调用 Jev 做结构化判断、LLM 写回复；必须准确标明来源，不把调用失败伪装成成功。
- 微信 H5 的最小路径是粘贴与复制。没有能力自动读取或发送私人微信聊天；后续 HTTPS 部署与真机验收单独记录。
- `clients/android` 和 `clients/ios` 承载同一 H5，并通过微信官方 OpenSDK 分享编辑后的纯文本。真实联系人只能在微信内选择；关系下拉框不是联系人列表。未配置移动应用 AppID 时禁用原生分享并保留复制，不用虚构配置。
- 用户已确认当前个人主体无法创建移动应用，本阶段暂停 AppID 申请路线，优先网页复制回微信。系统分享是可选入口；从微信分享进本应用的接收入口尚未实现，不能混淆两个方向。Jev 账户已创建但密钥与真实调用仍未完成。
- 原生桥接仅信任配置的精确 HTTPS origin 和主 frame。只提交回复正文；SDK 接受交接不代表送达。取消、错误和未知结果保留当前草稿；导航或改稿后旧回调失效。iOS 没有 transaction，超时后本进程仅报告交接，不再归因迟到回调。

## 代码与验证

- 现有技术栈为 Node.js 22+、原生 HTML/CSS/JavaScript；视频用本地Python/PyAV/faster-whisper，公众号正文用小型HTML解析器。只增加实际读取内容所需依赖。
- API 为 `/api/config`、`/api/examples`、`/api/reply`。修改契约必须同步前端、服务器与测试。
- API 密钥只留在服务端环境；不要读取或打印 `.env` 和用户凭据。保留输入边界、超时中止、静态白名单、来源检查与并发限制。
- 工程检查运行 `npm test`；浏览器检查运行 `node tests/browser-smoke.mjs`，需要本机 Playwright 和 Chrome 路径。
- Android 使用已校验版本的 Gradle wrapper，运行 `testDebugUnitTest lintDebug assembleDebug`。iOS 需 Mac/Xcode 构建并执行 XCTest；Windows 的静态检查不能标成编译通过。详细客户端配置见 `CLIENTS.md`，当前没有 AppID 或微信真机验收记录。
- 更改后如实记录执行工具、结果和未验证项。由 Codex 写的文件不能标成 Kiro 生成；没有 Kiro 运行记录就不能声称 Kiro 已完成任务。
- 历史 Kiro CLI 已登录、加载当时的 Steering，随后受账号临时锁定阻断；本轮极简页面由 Codex 完成，更新这个文件不代表 Kiro 已重新运行。实际记录见 `KIRO.md`。
