# 知意 · 录屏与提交指南

## 先准备一个能复现的场景

准备一段允许公开演示的视频，以及非私人的测试聊天内容。保持本机后端、连接器和电脑版微信的视频号会话在线。不要同时展示私人联系人、群消息、密钥或会话参数。

录制前走一次：在微信打开原卡片 → 悬浮球或 Ctrl + Alt + R → 从微信接入 → 核对标题作者 → 生成 → 查看依据 → 编辑回复 → 复制返回。普通私有视频号卡片不支持直接当文件拖入；录屏请使用已走通的接入方式，不把拖拽失败藏在画面外。

若复用十分钟内的资料缓存，字幕写“复用已读取资料”；要展示首次处理速度，使用未分析过的视频或点“刷新依据”，并保留真实耗时。缓存命中不能包装成首次读取。

## 四分钟脚本

| 时间 | 画面与操作 | 可以这样讲 |
| --- | --- | --- |
| 00:00–00:20 | 微信里一条可公开分享的视频，旁边是收起的悬浮球 | “收到家人分享的长视频，想认真回应，却没时间逐条看完。” |
| 00:20–00:55 | 点开悬浮球，从微信接入，核对作者和标题，填写可选关系备注 | “打开原卡片一次后接入后台，选中真正想回复的这条，不根据封面猜内容。” |
| 00:55–01:40 | 点击生成，展示处理阶段与计时 | “本机转写完整音轨，再结合画面样本和真实评论分析。”等待可加速，字幕保留实际耗时。 |
| 01:40–02:30 | 依次看转写、分段摘要、高赞评论和回复样本 | “依据可以核对；评论热度不等于正确，数量表示这次读到的样本。” |
| 02:30–03:10 | 修改生成回复，复制返回微信；在安全的测试会话里粘贴，自己决定是否发送 | “关系备注影响语气，最后这句话仍由我改、由我发。” |
| 03:10–03:40 | 展示一项真实完成的 Kiro 任务及改动/测试 | **仅在任务成功后录入。** 当前尚未完成，不用设置文件或 Codex 记录代替。 |
| 03:40–04:10 | 打开统一仓库、网页与下载入口，收起悬浮窗 | “在线页无需安装，可看真实分析记录；分析自己的内容使用本机包和自己的账号。” |

成片控制在 3–5 分钟，带语音或完整字幕。不要为了节奏把未读到的内容、加载失败或模拟样例说成真实分析结果。

## README 可用的三张实机照片

1. **轻量入口：** 实际微信窗口旁的悬浮球，聊天区域使用非私人测试内容；体现用完即可收起。
2. **生成与编辑：** 实际悬浮窗选中的视频标题、回复对象备注与已生成回复；保留正常留白，避免把全部设置同时展开。
3. **有据可查：** 同一次分析的转写/分段和评论依据，包含实际点赞及样本说明。

从最终录屏截取清晰画面即可，不必另造宣传图。发布前核对截图和 Release 为同一版。遮盖私人信息时不要改写回复或把失败提示变成功；生成的预览图、示例页截图需分别标成“界面预览”“展示页”，不能称真实微信实测。

## 提交文件

- **链接：** `https://mtmt0111.github.io/xingyu/`
- **源码与下载：** `https://github.com/MTMT0111/xingyu`
- **视频：** 推荐 MP4，1080p、系统字号清晰；常用 H.264 编码便于播放。
- **压缩：** 成片单独放入 ZIP，总大小不超过 200 MB；不要把工作目录、依赖、密钥或微信数据放进去。
- **说明：** 使用 [SUBMISSION.md](../SUBMISSION.md) 的字段草稿。补上真实 Kiro 执行结果后再核对 50 字/200 字限制。
- **留档：** 记下 Release 版本、源码 commit、视频名称和 SHA256；最终提交成功后保存回执。

示例打包命令（把路径改成自己的最终视频，不覆盖已有文件）：

```powershell
Compress-Archive -LiteralPath 'D:\作品材料\知意-演示.mp4' -DestinationPath 'D:\作品材料\知意-演示提交.zip'
Get-Item -LiteralPath 'D:\作品材料\知意-演示提交.zip' | Select-Object Name, Length
Get-FileHash -LiteralPath 'D:\作品材料\知意-演示提交.zip' -Algorithm SHA256
```
