# 微信卡片接入与依据展示验收

日期：2026-10-21。

## 本次修复：原视频标识接入

主入口现为“从微信接入”（Ctrl+Alt+V）：先在微信点开原卡片一次，连接器取得实际视频标识，核对作者、标题和时间后选择。不必等待播放完，不使用 OCR 或关键词。直接拖拽私有卡片仍不支持，不能宣传为拖拽已修复。

修复连接器视频资料上报遗漏鉴权的问题；新增受本机鉴权保护的捕获记录接口，保留不透明 nonce 与 64 位 ID，拒绝错误标识、重复记录和非视频内容。仅保留最近 20 条，不公开媒体签名地址或密钥；重启后清空。微信推荐页也会捕获记录，所以不会自动选中最新一条。后端额外核对详情返回 ID 与用户所选 ID 一致，不一致就停止。

实际验证：在已登录的电脑版微信打开聊天引用的“老朱别胡说 / 利益为先 感情次之”原视频，接入标识与此前核对的原视频完全相同。后台读取 **23.966 秒、完整音轨转写 98 字、6 帧、5 条评论及回复**；第一次实际返回约 **13.6 秒**，生成源为真实模型。随后在正常 Windows 客户端选择原视频、填写“妈妈”及自然语气备注，并生成同一视频回复，未使用演示模式或合成输入。

“找相关视频”实际后台检索“人际关系真心”返回 12 条候选。候选清楚标为尚未阅读，不混入原视频依据；只能在取得有效分享地址时复制链接，否则复制标题和作者供微信查找。回复生成加强按关系表达、避免空泛礼貌套话和批评式开场，仍由用户审阅编辑。

工程验证：82 项 Node 测试、Windows 编译与自检通过；连接器 handlers/router 测试通过，新增用例覆盖去重、20 条上限、原始标识保留、非法输入和资料脱敏。原始本机结果只存于忽略提交的 work 目录。

本次观察到视频号页面关闭后会话不可用，接口明确报错，已有回复保留。恢复视频号首页后再次生成成功。该依赖仍然存在；移动端、OCR 定位的完整实机标定不在本轮验证范围。

## 较早版本：OCR 备用入口

问题：原入口只接收文件、文本和原分享链接，不能把聊天中视频号私有卡片当作视频文件。用户实测拖入失败；这不是已经解决的微信卡片拖拽兼容性。真实卡片右键菜单没有复制链接或另存视频入口，微信和助手均为普通权限进程。

新增路径：点击“选取微信视频”或按 Ctrl+Alt+V，框住一张卡片的标题与作者。本机 Windows OCR 识别选区后，自动把文字带入真实视频号搜索；用户核对作者和标题，选择原视频，再生成回复。不用手工输入关键词，不用打开或播放该视频。识别失败可以重选；检索失败、没有原视频时保留原输入，不拿相似视频或封面生成内容总结。

截图仅用于定位卡片，不上传给模型。后端收到的是明确选定的视频标识，按既有流程取得视频文件、音轨、采样画面与评论样本。普通文件和可复制的原分享链接仍可拖入。

本轮验证：

- Windows 客户端编译、自检通过；新增用例覆盖 OCR 中文空格、重复行、纯时间、空内容、长关键词和英文空格。
- 在真实电脑版微信执行 Ctrl+Alt+V，出现卡片选区并完成框选。随后观察到用户参与操作的真实助手已经生成对应视频总结和回复、显示 4 条评论/回复样本。未把工具未完整观察到的候选选择过程写成全自动 UI 验收。
- 独立真实后台复核：检索“利益即感情”，核对作者“老朱别胡说”对应候选；2026-10-21 15:05 完成读取 **23.961 秒、6 帧、完整音轨转写 98 字、4 条评论及回复**，模型为 `deepseek-flash`。数据来自已登录的微信会话，没有使用预置回复。私有原始结果留在忽略提交的 `work/channels-real-result.json`。
- 本机体验包包含相同新版 EXE，排除 `.env`、微信会话及对象备注。

边界：尚未接通微信任意私有卡片的直接拖拽；OCR 与搜索可能找不到原视频，必须核对候选。没有自动选择好友或代发消息。本轮不包含实体 Android 手机验证。
