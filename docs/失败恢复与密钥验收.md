# 失败恢复与密钥验证

日期：2026-10-21。

修复前：最终回复解析失败时，服务只返回泛化错误。窗口拿不到已完成的转写、摘要和评论，「已有文字已保留」实际只指输入，并不能找到读取资料。密钥窗口的状态区与说明重叠，初始查询又可能覆盖保存后的提示；网络异常还可能被误报为写入失败。

修复后：

- 统一不确定策略的两条可能理解要求，去掉与“1–2条”之间的冲突；格式检查返回具体字段问题，供自动修复使用。
- 最终 JSON 或必填字段不合格，只依据原始资料自动修复一次，仍失败就明确报错，不用本地模板冒充 AI。
- 失败响应带回已经取得的资料；「查看已读资料」直接进入原文转写页，评论及分段摘要分栏展示，可导出文本。旧回复草稿保留，失败响应不写入未经校验的回复。
- 最终回复失败后，10 分钟内可复用完整视频资料；部分画面分析失败仍展示已有转写和评论，标注未完成，重试需重新读取。缓存仅在本服务进程内、最多 8 条，关闭服务或过期后需重读。
- 密钥设置的初始查询完成前不可提交，避免旧查询覆盖新结果。验证新密钥与验证已保存密钥为两个明确操作，成功显示模型和时间；新密钥只有实际调用成功、文件写入成功后才显示已保存。服务重启后状态回到「已配置，尚未验证」，不冒充刚通过验证。
- 错误记录只含处理阶段和校验原因，不记录密钥、微信令牌、原文或模型原始响应。

工程验证：95 项 Node 测试、Windows 编译和自检通过。新增覆盖格式修复、最终失败资料返回、重试复用、画面失败的部分资料、网络与磁盘错误区分、验证原密钥不改写文件、Windows 失败响应解析。

实际验证：使用已登录微信中原「奶牛Denny」视频，时长 473.366 秒，读取 3 段完整音轨与画面摘要、200 条评论及回复样本；实际 DeepSeek Flash 成功生成 4 项依据分析和回复，首次耗时 84.4 秒。评论达到样本预算，不代表读完全部评论。已保存密钥通过 DeepSeek 实际请求验证（HTTP 200）；密钥及私有原始数据仅留本机忽略目录。

更新后的正式服务再次读取同一真实视频，确实遇到一次最终回复格式不合格；自动修复后返回 HTTP 200、5 项分析和自然回复，总耗时 89.1 秒，未重新下载或转写。窗口中的「验证已保存密钥」实际点击后显示绿色成功提示、模型与验证时间，截图为 `screenshots/windows-key-settings.png`。

限制：无法从旧版已丢弃的错误响应恢复转写，本次通过重新读取原视频取得资料。任意视频、网络与平台会话仍可能失败；格式自动修复最多一次。没有重测实体手机或第二台 Windows 电脑。
