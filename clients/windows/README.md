# 知意 Windows 悬浮助手

更新：2026-10-21。入口是 `downloads/zhiyi-windows.exe`，约 114 KiB，使用系统 .NET Framework / WinForms，没有 Electron 或新增运行依赖。

「服务 → DeepSeek 密钥 · 配置 / 更换」提供隐藏密钥输入、真实小额验证与本机保存，模型固定为官方 `deepseek-flash`。不回显现有密钥，失败保留原配置。分析时显示阶段和经过时间，可收起窗口继续；生成后自动检索并显示相关视频候选。资料保留在进程内 10 分钟用于快速换一句，点「刷新依据」重新读取。

## 使用

1. 启动本机连接器和 `npm start`，保持电脑微信登录并打开视频号首页。后台会话连接后，不需要播放目标视频。
2. 双击 Windows 助手；点击悬浮球或按 **Ctrl+Alt+R** 唤起/收起。
3. **微信视频号卡片拖不进时，在微信点开卡片一次，再点“从微信接入”或按 Ctrl+Alt+V**。核对标题、作者和接入时间，选择原视频，不需要等视频播放完。连接器直接提供实际视频标识，不经过 OCR。推荐内容也可能被记录，不自动选中任何一条。记录只保留连接器本次启动以来最近 20 条，重启后需重新打开卡片。视频文件或可复制的原链接仍可拖入；公众号链接可用“粘贴链接 / 消息”。
4. 填“回复对象”和“关系与习惯”，例如“妈妈 / 关系亲近，简短自然”。它们是用户提供的备注，不是自动读取的微信联系人。成功生成后仅在本机保存，最多 30 个对象。
5. 点“生成回复”。后台取得真实视频、语音和评论样本后生成；点“查看依据”在独立页签核对摘要、转写、分段与评论，保留点赞数及上下级回复关系。编辑后“复制 · 回到微信”，再在正确的微信聊天里粘贴并确认发送。直接导入的视频文件不含评论区身份。
6. “找相关视频”按本次内容提出话题并实际检索。候选尚未阅读，可选择进一步分析；选择新视频才替换当前素材，取消保留原回复。有可验证原链接才提供链接复制，否则只复制作者和标题供微信搜索后转发原卡片。

新机器无需克隆私有仓库，使用 [本机体验包](https://github.com/MTMT0111/haohaohui-demo/releases/tag/desktop-2026.10.21)，先 `setup.cmd`，之后 `start-local.cmd`。长视频改为流式上传，512 MiB 上限，没有 60 秒时长限制。关系备注支持多行显示；切换到新对象时清空之前对象的备注。

右键菜单保留“框选卡片查找（备用）”：本人框选后在本机 OCR，识别文字只用于搜索，准确度受字体、缩放和遮挡影响，必须核对候选。主入口“从微信接入”不使用截图，也不尝试解密聊天数据库。悬浮球可拖动，右键可恢复跟随或退出。

对象备注位于 `%LOCALAPPDATA%/Zhiyi/recipients.json`，只保存本人输入的称呼和习惯，不保存聊天全文或推测的人格。服务地址在同目录 `desktop-service.txt`。模型密钥只在服务端。

## 真实验收

2026-10-21 后台搜索原视频与已取得的真实分享链接分别跑通。取得 38.313 秒视频，6 帧、语音转写和 78 / 77 条评论样本，由 DeepSeek 生成回复。详见 [真实演示验收](../../docs/真实演示验收.md)。

构建执行 `./clients/windows/build.ps1`。脚本进行编译、自检并产生明确标记为合成文字的界面预览；预览不是实测依据。`--demo` 仍是用于布局调试的合成场景，提交演示应运行普通客户端。
